# AGENTS.md

This file provides guidance to AI agents when working with code in this repository.

## Developer Documentation

GuildKit is a pnpm monorepo. The frontend is a Next.js application, and the backend is an API-only Next.js application (Route Handlers only) built and deployed with [Vinext](https://github.com/cloudflare/vinext) on Cloudflare Workers.

#### Key Directories

- **projects/backend/src/app** - Web API implemented with Next.js Route Handlers
- **projects/backend/prisma** - Database schema and model definitions
- **projects/client/src** - API client used by the frontend
- **projects/shared/src/zod** - Zod schemas shared by the backend and the frontend
- **projects/guildkit/src/app** - Next.js pages using app directory
- **projects/guildkit/src/components** - Reusable React components
- **projects/guildkit/public** - Static assets and vendor files

### Architecture

- The frontend (`projects/guildkit`) is a Next.js application. It calls the backend through `@guildkit/client`.
- The backend (`projects/backend`) is an API-only Next.js application, run with Vinext (`vite dev`, `vite build`) and deployed to Cloudflare Workers with Wrangler.
- GuildKit uses [Prisma](https://www.prisma.io/docs/) as the ORM.
- GuildKit uses an S3-compatible object storage. It uses [`@aws-sdk/client-s3` npm package](https://www.npmjs.com/package/@aws-sdk/client-s3).
- GuildKit uses Podman Compose, which is compatible with Docker Compose, to run the database and object storage server on the local development machines.
- GuildKit uses pnpm instead of npm.
- GuildKit does not use npm scripts. We use [mise-en-place](https://mise.jdx.dev) instead. The tasks are defined in mise.toml and the files under .mise/tasks/.
- **Instance config**: `guildkit.config.ts` at the repo root is the per-instance user config, typed with `GuildKitConfig` from `@guildkit/shared/zod`. The backend reads it via `projects/backend/src/lib/config.ts`.
- **Storage**: `StorageClient` in `projects/backend/src/lib/storage.ts` builds an S3 client from `servers.storage` in the instance config (local RustFS in development, Cloudflare R2 otherwise).
- **Auth**: better-auth with the organization plugin. `initAuth()` is in `@guildkit/db`, the backend's instance is `auth` in `projects/backend/src/lib/auth.ts`, and the frontend's client is in `projects/guildkit/src/lib/auth/client.ts`. Users have a `type` (`candidate` | `recruiter`) and a `role` (`projects/db/src/auth/roles.ts`). Recruiters belong to organizations.
- **Web API**: Each endpoint is a Route Handler in `projects/backend/src/app/**/route.ts`.
  - Route Handlers use `prisma` and `auth` from `projects/backend/src/lib/`. They are module-level variables; `prisma` forwards to a PrismaClient created for each request because Cloudflare Workers cannot reuse a DB connection across requests.
  - Protected Route Handlers call `requireAuthAs(request, "recruiter" | "candidate" | "any", options)` from `projects/backend/src/lib/auth-guard.ts`. It returns `{ user, session }`, or an error `NextResponse` (401) that the handler must return as is. It also sets the active organization of recruiters.
  - Validate input with Zod schemas from `@guildkit/shared/zod` or `projects/backend/src/schemas/`, and return `{ errors: flattenError(error) }` with status 400 when validation fails. Other errors return `{ code, message? }`.
  - Document each Route Handler with the JSDoc tags of [next-openapi-gen](https://github.com/tazo90/next-openapi-gen) (`@tag`, `@path`, `@query`, `@body`, `@response`, `@add`, …). Schema names in the tags refer to Zod schemas in `projects/shared/src/zod` or `projects/backend/src/schemas`. Do not use commas or colons in the descriptions of `@response` and `@add`.
  - `mise build` generates the OpenAPI spec (`projects/backend/openapi/openapi.json`) and then `@guildkit/client`'s types with openapi-typescript.
- **Component split**: Interactive components are split into `X.tsx` (server) and `X.client.tsx` (client), e.g. `JobEditor`, `OrgEditor`, and `app/auth/page.client.tsx`.
- **Errors**: Thrown errors include a unique code such as `GK-9JFB6` to make them traceable.

### Quick Start

1. `cp .env.example .env` (required: setup tasks need `SERVER_ENV`)
2. Start the Podman daemon
3. `mise install`
4. `mise build`
5. `mise dev`

### Commands

Run tasks via mise, never npm scripts. Root tasks (`mise dev`, `mise build`, `mise lint`, `mise fix`) fan out to `//projects/...:<task>` in each project's `mise.toml`.

- `mise install` - Install all dependencies, including npm dependencies.
- `mise dev` - Start dev servers including the frontend (port 3000), the backend (port 3001), database server, and object storage server.
- `mise build` - Build application.
- `mise lint` - Run `tsc --noEmit` and ESLint.
- `mise fix` - Fix linting issues.
- `mise clean` - Delete the Docker containers and gitignore'd files except for .env and mise.local.toml.
- `mise refresh` - Recreate the Docker containers and pnpm-lock.yaml, and update pnpm.
- `mise ai-postedit` - Syncs generated files, then runs `tsc --noEmit`, the project lint tasks, and `eslint --fix`. Use it to check your edits.
- `mise build` (in `projects/backend`) - Regenerates the Prisma client and better-auth schema, applies migrations, seeds dev data, generates the OpenAPI spec, and builds the backend.
- `mise seed` (in `projects/backend`) - Seeds the DB. It only runs when `SERVER_ENV` is `development`, `demo-production`, or `demo-preview`, and only when the DB is empty.
- `mise deploy` (in `projects/backend`) - Builds and deploys the backend to Cloudflare Workers.

There is no test suite yet. The root `mise test` task exists, but no project defines a `test` task.

### Environment variables

- `SERVER_ENV` is required by the setup and build tasks. Copy `.env.example` to `.env` for local development (`SERVER_ENV=development`). mise loads `.env` automatically.
- In `development`, `mise setup` starts Postgres and RustFS (an S3-compatible store) with `compose.yaml` and creates the bucket. The RustFS console is at http://localhost:9001.
- The backend runs on workerd even in development. It reads the environment variables from `projects/backend/.dev.vars`, which is a symlink to `.env`. On Cloudflare Workers, they are available as `process.env.*` with the `nodejs_compat` compatibility flag.

## Rules

- Wording: An **organization** is the hiring company. A **recruiter** is a staff user who belongs to an organization. Use **employer** only when you mean both.
- Use the `@/` path alias for `projects/guildkit/src`, and include the `.ts`/`.tsx` extension in import paths. The backend uses relative import paths.
- Do not edit gitignored files.
- After you update the code, check AGENTS.md and find if there is anything outdated. If there is any outdated content, update or delete it.
